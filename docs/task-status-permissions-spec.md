# タスクステータス・権限仕様書

## 文書情報

- バージョン: 1.2
- ステータス: 実装対象
- 関連仕様: [写真登録・確認機能仕様書](task-photo-feature-spec.md)

## 1. 目的

タスクのステータスと、User・Leader・Adminが実行できる操作を定義する。

写真の形式、変換、アップロード、保存、表示および運用については、写真登録・確認機能仕様書で定義する。

## 2. タスクステータス

|  値 | ステータス |
| --: | ---------- |
|   0 | 未着手     |
|   1 | 進行中     |
|   2 | 確認中     |
|   3 | 完了       |

写真を登録または削除しても、ステータスは自動変更しない。

写真が0枚でも、確認中および完了へ変更できる。

## 3. ロール別権限

各操作は、対象タスクを閲覧または操作できる範囲に限る。

| 操作                       | User | Leader | Admin |
| -------------------------- | :--: | :----: | :---: |
| 写真の閲覧                 |  可  |   可   |  可   |
| 未完了タスクへの写真登録   |  可  |   可   |  可   |
| 未完了タスクの写真削除     |  可  |   可   |  可   |
| 完了タスクの写真登録・削除 | 不可 |  不可  | 不可  |
| 未着手への変更             | 不可 |   可   |  可   |
| 進行中への変更             | 不可 |   可   |  可   |
| 確認中への変更             | 不可 |   可   |  可   |
| 完了への変更               | 不可 |  不可  |  可   |
| 完了後の差し戻し           | 不可 |  不可  |  可   |

写真は登録者本人に限らず、対象タスクの写真操作権限を持つユーザーが削除できる。

## 4. User

- ステータスを変更できない。
- ステータスは読み取り専用で表示する。
- 未完了タスクでは写真を登録・削除できる。
- 完了タスクでは写真を閲覧できるが、登録・削除できない。

## 5. Leader

- 未着手・進行中・確認中へ変更できる。
- 完了へ変更できない。
- 完了済みタスクを差し戻せない。
- 未完了タスクでは写真を登録・削除できる。
- 完了タスクでは写真を閲覧できるが、登録・削除できない。

## 6. Admin

- すべてのステータスへ変更できる。
- 完了へ変更できるのはAdminのみとする。
- 完了済みタスクを差し戻せるのはAdminのみとする。
- 未完了タスクでは写真を登録・削除できる。
- 完了中は写真を閲覧できるが、登録・削除できない。

## 7. 完了状態の不変条件

完了中は、Adminを含むすべてのロールが写真を追加・削除できない。

Adminは、完了から以下のステータスへ差し戻せる。

- 未着手
- 進行中
- 確認中

差し戻しと写真変更は同時保存できない。

1. Adminが差し戻しだけを保存する。
2. クライアントがタスクを再取得する。
3. 新しい変更操作として写真を編集する。

完了状態のまま写真だけを変更することはできない。

## 8. 写真変更とステータス変更の同時保存

タスク行をロックした時点の現在ステータスが未完了の場合、権限のある範囲で写真変更とステータス変更を同じ変更セットに含められる。

例:

- User: 写真変更のみ
- Leader: 写真追加と、進行中から確認中への変更
- Admin: 写真追加と、未完了から完了への変更

DB上では写真変更を先に適用し、その後ステータスを変更する。

写真操作の可否は、変更先ではなくロック取得時点の現在ステータスで判定する。

## 9. サーバー側の権限検証

画面上で操作を制限するだけでなく、サーバー側でも以下を検証する。

- ログイン状態
- ユーザーのロール
- 対象タスクの閲覧・操作権限
- ロック取得時点の現在ステータス
- 変更先ステータス
- 完了後の操作制限
- タスクのロックバージョン

クライアントから直接リクエストされても、権限のない操作は拒否する。

写真アップロード前の事前確認は早期拒否のための最適化であり、保存確定トランザクション内の検証を省略しない。

## 10. 楽観ロック

タスクに **lock_version** を保持する。

以下の操作が成功するたびに、同じDBトランザクション内で値を増加させる。

- 写真追加
- 写真削除
- ステータス変更
- その他のタスク更新

クライアントは、タスク取得時の **lock_version** を保存操作へ付与する。

保存確定時はタスク行をロックした後、現在値と比較する。不一致の場合は自動上書きしない。

```json
{
  "code": "task_version_conflict",
  "message": "タスクがほかのユーザーによって更新されました。再読み込みしてください。"
}
```

競合後の写真ファイル再利用については、写真登録・確認機能仕様書で定義する。

## 11. タスク削除

タスク削除の実行権限は既存のタスク削除仕様に従う。

タスク削除は現行実装どおり、**tasks.deleted** に削除日時を設定する論理削除とする。写真機能の追加を理由に、タスクを物理削除へ変更しない。

タスク削除時の写真ファイル、監査ログおよびGC処理については、写真登録・確認機能仕様書で定義する。

## 12. 受け入れ条件

- Userがステータスを変更できない。
- Leaderが未着手・進行中・確認中へ変更できる。
- Leaderが完了へ変更できない。
- Adminのみ完了へ変更できる。
- Adminのみ完了済みタスクを差し戻せる。
- 未完了タスクでは全ロールが写真を登録・削除できる。
- 完了後はAdminを含め写真を変更できない。
- 未完了タスクでは、権限範囲内のステータス変更と写真変更を同時保存できる。
- 完了からの差し戻しと写真変更は同時保存できない。
- 写真操作だけではステータスが変わらない。
- 写真が0枚でもタスクを完了できる。
- 競合時にほかのユーザーの変更を自動上書きしない。
- タスク削除時にタスクと有効な写真を同じDBトランザクションで論理削除できる。
