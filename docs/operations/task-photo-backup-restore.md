# タスク写真のバックアップ・復元手順

## 文書情報

- バージョン: 1.0
- ステータス: 運用手順
- 関連仕様: [写真登録・確認機能仕様書](../task-photo-feature-spec.md)

v1.5の写真登録・確認機能仕様書 §29・§30 に記載していたバックアップ・復元手順を、実装ではなく運用手順であるためこちらへ切り出した（v1.6での変更）。内容そのものは変更していない。

## バックアップ

DBバックアップとマニフェストは、同一DBスナップショットから取得する。

マニフェストには次を含める。

- 写真ID
- タスクID
- メイン画像の保存キー・容量・SHA-256
- サムネイルの保存キー・容量・SHA-256
- 論理削除状態

手順:

1. バックアップとGCの排他ロックを取得する。
2. DBスナップショットを開始する。
3. 同じスナップショットからDBバックアップを取得する。
4. 同じスナップショットからマニフェストを生成する。
5. マニフェストに含まれるメイン画像とサムネイルをVolumeから取得する。
6. 件数・容量・SHA-256を検証する。
7. DB、マニフェスト、画像を同一世代として保存する。
8. 排他ロックを解放する。

バックアップ中はGCを実行しない。GC実行中は、GC完了後にバックアップを開始する。

排他ロックには有効期限とハートビートを持たせ、異常終了による永久ロックを防ぐ。

スナップショット時点で有効だった写真は、その後論理削除されてもマニフェストに含まれる。

### 運用値

- 頻度: 1日1回
- 保持: 7世代
- 通常想定所要時間: 24時間以内
- 許容上限: 48時間
- 物理ファイル削除猶予: 72時間
- Volume使用率80%で通知
- 定期的に復元テストを行う

48時間を超えたバックアップは失敗として通知する。

物理ファイル削除猶予72時間（写真登録・確認機能仕様書 §26 のタスク削除GC猶予と同じ値）は、バックアップ許容上限48時間に24時間の安全余裕を加えた値である。MVPの初期運用値として採用し、Volume使用量と復旧実績に応じて見直す。

## 復元

1. アプリケーションとGC処理を停止する。
2. リバースプロキシでメンテナンス画面を返す。
3. DBを一時環境へ復元する。
4. 同一世代のマニフェストを読み込む。
5. メイン画像とサムネイルを一時Volumeへ復元する。
6. 件数・容量・SHA-256を検証する。
7. DBレコードと保存キーの対応を確認する。
8. DBとVolumeを切り替える。
9. 整合性確認を再実行する。
10. アプリケーションを再開する。

Docker Volume自体を削除してから復元を開始してはならない。

### 復元時の判定

- DBバックアップ破損: 中止
- マニフェスト破損: 中止
- メイン画像欠損またはSHA-256不一致: 中止して運用者判断
- サムネイルだけ欠損: 復元を続行
- 欠損サムネイル: メイン画像から再生成
- 再生成後: 容量・寸法・SHA-256をDBへ反映

### サムネイル再生成時の注意

WebPエンコーダの種類やバージョンが異なる場合、同じメイン画像と設定から再生成しても、サムネイルのバイト列とSHA-256が復元前から変わることがある。

これは直ちに破損を意味しない。

再生成後の実ファイルから容量、寸法およびSHA-256を取得してDBを更新し、運用ログに次を記録する。

- 対象写真ID
- 復元前のSHA-256
- 復元後のSHA-256
- 使用したエンコーダとバージョン
- 再生成日時

以後のETagとバックアップマニフェストには、再生成後のSHA-256を使用する。
